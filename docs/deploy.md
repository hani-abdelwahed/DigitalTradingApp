# Putting the demo online

The demo runs on [Render](https://render.com)'s free tier: one web service (the API, which also serves the web app), a Postgres database and a Redis-compatible cache, all in Frankfurt. Everything is described in [`render.yaml`](../render.yaml), so setting it up takes a few clicks and no server work.

## What you need

- A Render account. Sign up with GitHub at https://dashboard.render.com/register. It's free, and no card is needed for the free tier.
- Optional: a free [Alpaca](https://alpaca.markets) account, for real US stock prices. Without it, stocks show clearly labelled simulated prices. Crypto prices are real either way.

## Steps

1. In Render, choose **New → Blueprint**.
2. Connect GitHub when asked, and give Render access to the `DigitalTradingApp` repository.
3. Pick the repository and the `main` branch. Render reads `render.yaml` and lists three resources: `digitaltradingapp`, `digitaltradingapp-db` and `digitaltradingapp-cache`.
4. It asks for `ALPACA_KEY_ID` and `ALPACA_SECRET_KEY`. Paste your Alpaca paper-trading keys, or leave both blank.
5. Click **Apply**. The first build takes a few minutes.
6. Open the service's URL, shown at the top of its page (for example `https://digitaltradingapp.onrender.com`). Create an account and trade.

Every merge to `main` deploys automatically afterwards. Secrets (`JWT_SECRET`, `ENCRYPTION_KEY`) are generated by Render once and never leave it.

## Free tier limits

| Limit | What it means for the demo |
| --- | --- |
| The web service sleeps after 15 minutes without visitors | The first visit after a quiet spell takes up to a minute while it wakes. Resting orders (limit, stops) are not checked while it sleeps; they are checked again as soon as it wakes. |
| The free database expires 30 days after it is created | Fine for a short demo. To keep it, switch the database to a paid plan in Render before then. |
| The cache is not saved to disk | Rate-limit counters and manual halts reset when it restarts. Accounts, orders and balances are in Postgres and are not affected. |
| 750 free instance hours a month | Enough for one service running all month. |

## Running the kill switch on Render

Open the service's **Shell** tab and run:

```sh
node apps/api/dist/scripts/halt.js on all "Maintenance"
node apps/api/dist/scripts/halt.js off all
```

The Shell tab is not available on the free plan. Until you upgrade, the volatility circuit breaker still works automatically.

## Elsewhere

Any Node.js 22 host works. Build with `pnpm install && pnpm build`, set the variables from `apps/api/.env.example` plus `WEB_DIST_DIR=apps/web/dist` and `NODE_ENV=production`, and start with `node apps/api/dist/db/migrate.js && node apps/api/dist/server.js`. In production, `WEB_ORIGIN` must be the https address people visit.
